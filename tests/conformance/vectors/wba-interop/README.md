# Web Bot Auth interoperability fixtures

Copied without modification from adcontextprotocol/adcp-client
`test/fixtures/wba-interop/` at commit
`577f21e82a7c9f640e69d073f0856700f3601fe7` (adcp-client#3250, on `main` as of
`d6fe8b19585d846027aa6c896182b129cc04218d`), on 2026-10-15. `UPSTREAM.json`
records each file's SHA-256.

The fixtures were generated by adcp-client's `test/lib/wba-interop.test.js`
against Cloudflare's reference packages (`web-bot-auth@0.2.0`,
`http-message-sig@0.3.0`). Each is a request signed by one implementation, the
key directory to serve for the signer's origin, the verifier clock
(`reference_now`), and the expected outcome, including the RFC 9421 signature
base.

- `adcp-client-signed-*`: signed by adcp-client's `signWebBotAuth`, directory
  from `createSignedSignatureDirectory`.
- `cloudflare-signed-*`: signed by `web-bot-auth`'s `sign()` (padded base64
  nonce), directory signed with `http-message-sig` (Appendix B).
- `*-percent-encoded-path`: the target URI is `/a%7Eb/mcp/`; `@target-uri` is
  the URI as received (RFC 9421 §2.2.2), never percent-decoded.

`keys.json` holds test-only keys (`_private_jwk_for_test_only`). Never use them
outside tests. `tests/conformance/signing/test_wba_interop.py` verifies every
fixture with this SDK.
